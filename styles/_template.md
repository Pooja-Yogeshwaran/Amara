# [Style family name]

> Copy this file to `styles/<kebab-case-name>.md`, fill it in, then add one line for it to the list in `references/style-taxonomy.md`. That's the whole integration — nothing in `SKILL.md` or the schema needs to change to add a family.

- **Color harmony:** which of monochromatic / analogous / complementary / triadic / split-complementary this family defaults to, and why (see `references/color-theory.md` for the model list).
- **Type:** default UI face, default message-body face (can differ from UI for a real pairing — avoid defaulting both to the same grotesque), default monospace. Weight cap (2-3 max).
- **Shape:** corner-radius tendency, border treatment, elevation/shadow character (hard-offset vs. soft-blur vs. near-flat).
- **Motion:** default `iconTier` (static / micro-interaction / lottie / gif / video-loop) and general easing character (snappy, soft, blunt, editorial...).
- **Voice:** tone defaults — formality level, emoji frequency default (see `references/input-modes.md` emoji policy), sentence rhythm.
- **Accessibility note (if any):** does this family carry a structural accessibility tension the way Neumorphism does with low-contrast embossing? State it plainly and give the mitigation, don't bury it.

## Where it sits on the spectrum

One or two sentences placing this family relative to its neighbors on the continuous spectrum (e.g. "sits between Claymorphism and Playful/Funky — shares Clay's tactile shadow language but leans flatter and less saturated").
